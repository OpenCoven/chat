# OpenCoven Chat v0.0.8

This release fixes the Linux AppImage on newer distributions. On Ubuntu 24.04 and similar
systems, the AppImage's **Install Coven** step used to stop at the engine with *"The engine
install did not finish: Error: download failed"*. The AppImage now reaches the chat from an
empty profile, the same as the `.deb`. **Nothing else about the app changed since v0.0.7.**
On macOS and Windows, updating is optional.

Like the earlier versions, this is an early `0.x` pre-release without auto-update. Download
newer versions from the Releases page.

## Fixed: the AppImage on newer Linux

The AppImage runtime starts Chat with variables that point library, plugin and data paths
into the image, and Chat passed them on to every program it started. On Ubuntu 24.04 the
system's `curl` then loaded an older library from the image and failed, so the engine never
downloaded ([#525](https://github.com/OpenCoven/chat/issues/525)).

Programs Chat starts now get the environment Chat itself was launched with: the Coven CLI,
setup's installers, the archive extractor, and the hand-off to your browser. Outside an
AppImage nothing changes. If you worked around this on v0.0.6 or v0.0.7 by installing the
engine from a terminal, no further step is needed: the installed engine is found as before.

## Before you install

**Windows.** Two installers are published for 64-bit Windows 10 and 11 on x64 processors:
`OpenCoven.Chat_0.0.8_x64_en-US.msi` and `OpenCoven.Chat_0.0.8_x64-setup.exe`. Either one is
fine: the `.exe` installs for your user only, the `.msi` for everyone on the computer. There is
no build for Windows on ARM.

Neither installer is signed. The first time you run one, Windows SmartScreen shows **Windows
protected your PC** with an *Unknown publisher*. To continue:

1. Check the download first. In PowerShell:

   ```powershell
   Get-FileHash -Algorithm SHA256 .\OpenCoven.Chat_0.0.8_x64-setup.exe
   ```

   The hash must match that file's line in `SHA256SUMS` from the same release.
2. In the SmartScreen dialog, choose **More info**, then **Run anyway**.

**macOS and Linux.** As before: the disk images are notarized, and the Linux `.AppImage` and
`.deb` are unsigned. If anything Chat needs is missing, it opens on **Set up Coven Chat**
instead of the chat.

To check any download, run this in the folder that holds it and `SHA256SUMS`:

```bash
shasum -a 256 -c --ignore-missing SHA256SUMS
```

## Behind the scenes

- The AppImage that CI installs and drives is now built on Ubuntu 22.04, exactly as a release
  builds it, and then run on Ubuntu 24.04. That is the combination that showed the bug, and the
  lane now checks what the programs Chat starts actually receive.
