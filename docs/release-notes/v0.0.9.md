# OpenCoven Chat v0.0.9

Familiars can now ask you for permission. Chat runs every message read-only, so a familiar that
needed to change a file could only tell you it couldn't, and there was nothing you could click.
Now it asks, you answer on your Mac or your iPhone, and Chat keeps a log of what you allowed and
what the familiar then did.

Like the earlier versions, this is an early `0.x` pre-release without auto-update. Download
newer versions from the Releases page.

## New: asking for permission

When a familiar can't finish something read-only, it says what it wants to do and why. A card
appears above the message box, and the sidebar shows **Asks permission** beside its name.

- **Allow once** runs one more turn with full permission, then Chat goes back to read-only. That
  turn runs as you, on this computer. It can do anything your user account can, and it isn't
  limited to what the card describes, so read the request before you allow it.
- **Decline** runs nothing and leaves a line in the chat. The familiar is told on your next
  message.

A request closes when you answer it, an hour after it was made, or when you send that familiar
another message. A familiar can't answer its own request, and one answer starts one turn.

**Settings › Access** now has a **Permission log**, newest first: each request, your answer and
where you gave it, and each tool call Coven reports during the turn you allowed. If Chat can't
write to the log, it stops the turn rather than run it unrecorded.

Your Coven and familiar settings are unchanged, and nothing runs with full permission until you
answer a request.

## What it can't do yet

- **Codex familiars.** Coven doesn't report Codex's tool calls, so the log holds your answer but
  not what the familiar did with it. Coven Code and Claude Code familiars log each tool call.
- **Waiting requests aren't announced.** Chat sends no notification, on the Mac or on the iPhone.
  You see a request when the app is open.
- **A familiar has to ask.** A familiar that doesn't ask still only tells you it couldn't finish.
  Reply and ask it to request permission.

## Before you install

**Windows.** Two installers are published for 64-bit Windows 10 and 11 on x64 processors:
`OpenCoven.Chat_0.0.9_x64_en-US.msi` and `OpenCoven.Chat_0.0.9_x64-setup.exe`. Either one is
fine: the `.exe` installs for your user only, the `.msi` for everyone on the computer. There is
no build for Windows on ARM.

Neither installer is signed. The first time you run one, Windows SmartScreen shows **Windows
protected your PC** with an *Unknown publisher*. To continue:

1. Check the download first. In PowerShell:

   ```powershell
   Get-FileHash -Algorithm SHA256 .\OpenCoven.Chat_0.0.9_x64-setup.exe
   ```

   The hash must match that file's line in `SHA256SUMS` from the same release.
2. In the SmartScreen dialog, choose **More info**, then **Run anyway**.

**macOS and Linux.** As before: the disk images are notarized, and the Linux `.AppImage` and
`.deb` are unsigned. If anything Chat needs is missing, it opens on **Set up Coven Chat**
instead of the chat.

To check any download, run this in the folder that holds it and `SHA256SUMS`:

```bash
shasum -a 256 -c --ignore-missing SHA256SUMS
```

## Behind the scenes

- The packaged-app acceptance run now covers this path, using the installed app, Coven and the
  engine with a scripted model: a familiar's write is refused, it asks, and the file appears only
  after **Allow once**. After **Decline**, it doesn't.

## iPhone

The companion gains the same card. TestFlight build 0.3.0 shows a familiar's request, asks you to
confirm **Allow once**, and has the log at **⋯ › Permission Log**. The turn runs on your Mac, as
it would if you had clicked there.

To answer from the phone you need both Chat 0.0.9 on the Mac and companion 0.3.0. Companion 0.2.0
keeps working with Chat 0.0.9, but it can't show requests, so answer them on the Mac. Companion
0.3.0 works with earlier versions of Chat, which never ask.
