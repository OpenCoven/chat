# Coven Chat v0.1.3

Coven Chat now updates itself, and familiar chats signed in with a Claude subscription get the full access they were meant to have. This release follows v0.1.2. Install it: earlier versions can't update themselves, and their Claude-subscription chats were refused commands that full access allows.

## Coven Chat updates itself

Chat checks for a newer release a few seconds after it opens. To check again, open **Settings › About** and choose **Check for updates**. When an update is available, a dot appears on the gear, and **About** shows the new version and its notes. Nothing installs until you choose **Restart to update**. Chat then downloads the update, checks its signature against the key built into the app, installs it, and restarts. **Restart to update** waits while a familiar is replying, because restarting would end the reply. If a check or an install fails, **About** says so, and **Copy update details** copies the full error.

This is the first release that can update itself. Install it by hand from the Releases page; later versions arrive through **Check for updates**.

## Fixed: full access in chats signed in with a Claude subscription

When a chat used your Claude subscription through Claude Code (no API key and no engine sign-in), Coven's engine started Claude Code without the full-access setting. The familiar was refused commands such as listing a folder outside its project or running a loop, although **Settings › Access** said **Full access**. Chats that use an API key or the engine's own sign-in were not affected.

The fix is in Coven's engine 0.9.1 and later. A new install of Chat sets up Coven 0.4.10, and its engine step installs engine 0.9.1. If Coven is already installed with an engine older than 0.9.1, or with one whose version Chat can't read, no chat runs on it. Chat opens on setup until the engine is updated: under **Coven engine**, choose **Update the engine**, or run the command it shows in a terminal. When the update finishes, Chat checks which engine Coven now starts. If it's still an older one, the step fails and names that engine. Your familiars, chats and sign-ins are kept. If you set `COVEN_ENGINE_BIN` to choose your own engine, Chat doesn't replace it; setup says to update that engine or remove the variable.

If Claude Code itself is too old for the engine, the run now says **Claude Code is too old for this version of Coven. Run claude update in a terminal, then use Try again.**, instead of a generic failure.

## Settings › Model

- **Current presets.** **Every message** offers GPT-6 Astra, GPT-6.1 Sol, GPT-6.1 Terra and GPT-6 Luna, and Claude Fable 5.2 alongside Opus, Sonnet and Haiku 5.5. In Coven Code, the GPT choices use your Codex sign-in. Older saved model IDs stay editable under **Custom model** and are sent unchanged.
- **Each engine keeps its own choice.** A Claude model chosen for Coven Code is no longer sent to a Codex conversation, which failed with a ChatGPT account error ([#638](https://github.com/OpenCoven/chat/issues/638)). Switching engines keeps each engine's choice.

## Also fixed

- **Why a chat is locked, read aloud.** When Coven can't load the chosen familiar's chat, focus moves to the message that says why, so VoiceOver and Orca read it ([#592](https://github.com/OpenCoven/chat/issues/592)).
- **Settings › Access on Windows.** Chat now reads Coven Cave's project grants on Windows. **Refresh project access** lists the familiar's declared projects, and the composer's **#** suggestions offer them ([#587](https://github.com/OpenCoven/chat/issues/587)).
- **When Coven can't reach the model's server.** The error notice names the server, for example **Coven couldn't reach chatgpt.com, so this run stopped. Check your internet connection, then use Try again.** The report kept as the chat's last line leaves out the engine's own warnings, which never explain a failure ([#686](https://github.com/OpenCoven/chat/issues/686)).
- **The setup command, read aloud on Linux.** Screen readers on Linux now read the command next to **Copy command** on the setup screen, instead of an empty item ([#590](https://github.com/OpenCoven/chat/issues/590)).

## Known issues

- **Missions still need a newer Coven.** The inspector's **Missions** tab says **Missions need a newer version of Coven**, as it did in v0.1.2. Chat installs Coven 0.4.10, which can't take missions. A later release moves Chat to a newer Coven.
- v0.1.2's one known issue, Settings › Access on Windows, is fixed above.

## Before you install

This is an early `0.x` prerelease. It updates itself from now on (see above); install this version by hand. The desktop release supports macOS on Apple silicon and Intel, Windows on x64, and Linux on x64. On Linux, Coven and its engine need glibc 2.39 or newer (Ubuntu 24.04 or later, for example), and the engine needs the ALSA library (`libasound2t64` on Ubuntu). On older systems such as Ubuntu 22.04 or Debian 12, Chat opens but its setup can't finish. That was already true of v0.1.2. It was tested with Coven 0.4.10 and Coven's engine 0.9.1. The iPhone companion is distributed separately through TestFlight; builds 0.2.0 and 0.3.0 work with this desktop version.

The macOS app and disk images are signed and notarized. Windows and Linux installers are unsigned. Windows SmartScreen may show **Windows protected your PC** with an unknown publisher. Verify the download against `SHA256SUMS`, then choose **More info** and **Run anyway** if you want to install it.

Download `SHA256SUMS` alongside your installer. On macOS or Linux, hash the installer you downloaded; for example, for the Apple silicon disk image:

```sh
shasum -a 256 Coven.Chat_0.1.3_aarch64.dmg
```

Compare the hash with the line for that exact filename in `SHA256SUMS`. For Intel macOS or Linux, replace the example filename with your downloaded installer's filename.

On Windows, use `Get-FileHash -Algorithm SHA256` in PowerShell and compare the result with that installer's line in `SHA256SUMS`.
