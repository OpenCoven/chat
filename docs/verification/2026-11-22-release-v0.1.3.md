# Coven Chat v0.1.3 release verification

This record separates the source and candidate evidence from the published installers and their acceptance runs. v0.1.3 is the first release that updates itself, and it gives chats signed in with a Claude subscription the full access they were meant to have, through Coven's engine 0.9.1. On 2026-11-22, Val chose to ship it on Coven 0.4.10 rather than wait for Coven v0.5.1 ([decision](https://github.com/OpenCoven/chat/issues/635#issuecomment-7075923162)). Chat's setup installs engine 0.9.1 itself when Coven's own choice is older (#647), so the engine's security fixes ship anyway. The Coven repin moves to v0.1.4.

## Verification before publication

- **Release dry run** from `main` against `v0.1.2` (`dry_run=true`): [run 44998407904](https://github.com/OpenCoven/chat/actions/runs/44998407904). Every job succeeded. **Publish GitHub release** and **Point the auto-update feed** were skipped, and v0.1.2 is unchanged.
- **Updater artifacts:** v0.1.2's tree has no updater, so the dry run can't build them. They were rehearsed on 2026-11-16 at the prep commit with a throwaway key ([comment](https://github.com/OpenCoven/chat/issues/635#issuecomment-6905354684)). `release-signing` held both `TAURI_SIGNING_*` secrets.
- **Native candidate run** on `22abc18`: [run 44999344307](https://github.com/OpenCoven/chat/actions/runs/44999344307), `asking=as-built`. 73/73 rows observed: 18 on each macOS DMG lane and on the Linux deb, and 19 on the Windows MSI. None failed or was blocked, and every lane report names `22abc18`.

## Limits retained

The native evidence comes from fresh CI users on hosted runners, not a hand-run on a person's machine. Native automation uses the real installed app, Coven CLI and engine with an API-key sign-in and a local model fixture. It doesn't establish live provider behavior or Claude subscription sign-in. The keyless hand checks on engines 0.9.1 and 0.9.2 are recorded on #635 (State, 2026-11-19). Physical iPhone behavior and human screen-reader acceptance aren't established either. Published native acceptance covers the two macOS DMGs, the Windows MSI and the Linux deb. The AppImage and deb also passed packaged acceptance. The Windows setup EXE has checksum and release-smoke evidence only. The deb's `Replaces`/`Conflicts`/`Provides` upgrade from v0.1.1 (#699) isn't natively driven. Its evidence is #699's isolated dpkg reproduction, and #520's installer rows stay hand-run. Windows signing (#411) and updater acceptance across two releases (#539) keep their existing limits.
