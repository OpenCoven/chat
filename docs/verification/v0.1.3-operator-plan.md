# Run the v0.1.3 installed-app checks

Val selected the published v0.1.3 installers for the outstanding hand-runs on 2026-11-23. Use this plan on each desktop you actually exercise. All rows below are operator instructions. Record results in the linked issues. The [release verification record](2026-11-22-release-v0.1.3.md) holds the automated observations, checksums and notarization receipts.

## Prepare a lane

Use a disposable OS account or VM with its own Chat app data and webview storage. Verify the isolated data path before launching; setting only `COVEN_HOME` leaves Chat data shared. Use synthetic conversations and keep any active personal installation and session intact. Give each installer format a separate profile or snapshot so you can retain its installed copy for the next release.

Download the matching file and SHA256SUMS from the [v0.1.3 release](https://github.com/OpenCoven/chat/releases/tag/v0.1.3). Compare the full hash against the exact filename with `shasum -a 256 <file>` or PowerShell’s `Get-FileHash -Algorithm SHA256 <file>`. Record tag, source commit `22abc182332c5c6d5610bfcf24b0781f43368f21`, filename, hash, OS/build, machine and installer architecture, isolated data path and actual Coven/engine versions.

## At the installed window

1. Open **Settings → About** on each install. Record the displayed version (expected **0.1.3**) and whether Coven is connected. Attach the observation to the corresponding #520 installer row. For #539 step 1, also record the **Updates** row as it goes from “Checking for updates…” to “Up to date” and “You have the newest version, 0.1.3.” Press **Check again** and record the result and whether anything downloaded or restarted. These expectations apply while the feed serves 0.1.3. If it has advanced, record the offer and consult the release owner before updating. Optionally repeat offline and record “Couldn't check for updates,” **Try again** and **Copy update details**. [Updater evidence and operator handoff](https://github.com/OpenCoven/chat/issues/539#issuecomment-7080470328)
2. On macOS, open **Settings → Model**. Record the **Runs on** choices (Coven Code, Codex, Claude Code), **Model**, **Think longer** and **Speed**. Enter a syntactically invalid model ID, attempt a disposable send, and capture the validation, Settings → Model guidance, stopped send and intact draft. Restore the model. Start a new chat with a non-default harness; in **Overview → Runs on**, verify its harness and that an existing chat kept its original harness. Record both chat identities and settings (#520 rows 3–4).
3. On macOS with a Missions-incompatible Coven in the isolated profile (the historical refusal case uses 0.4.10), open **Missions** and press **Try again**. Record the actual CLI version, “Missions need a newer version of Coven. Update Coven, then choose Try again.”, the absent compose form and the repeated capability check. Capture a command/event trace showing no mission send and before/after evidence that no `coven-missions/` folder appeared (#520 row 5).
4. On each desktop, run the link review below. On macOS the first exact HTTPS handoff also covers #520 row 6.
5. On macOS, create a disposable chat with an attachment and retain an unrelated control chat and shared session. Record their IDs and the target’s transcript and attachment paths. Choose **Delete chat** for the target. Compare before/after listings and reopen the controls. Record removal of the target’s owned transcripts and `coven-attachments/<run>/` folder and survival of the unrelated data (#520 row 7). [Installer criteria and recording template](https://github.com/OpenCoven/chat/issues/520#issuecomment-7039468767)
