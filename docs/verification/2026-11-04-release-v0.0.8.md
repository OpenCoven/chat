## Native OS-level automation of the published installers (#504, #515; 2026-11-06)

A second lane, `scripts/native-acceptance/` (#549), drove the **published** installers on fresh GitHub-hosted runners. It used no WebDriver and no page script. Each installer was checked against `SHA256SUMS` and installed for a runner user with no prior `ai.opencoven.chat` data. The lane then completed first-run setup through the window, which installed the current Coven CLI and its engine.

The window was driven by the platform's own input: CGEvent on macOS, SendInput on Windows, XTEST on Linux. It was read back through AX, UI Automation and AT-SPI, and through VoiceOver, NVDA and Orca. This is the first lane to reach the published MSI: it avoids #532's debugging-port blockage because it attaches nothing to the web view. These are **not** hand-run results.

The findings, each with a focused issue against the owning feature:

- **#544**: on WebKit, Tab from a dragged passage that ends on a link drops **Quote selection**.
- **#545**: VoiceOver and Orca read no value on the inspector separator.
- **#546**: on Windows, composer text is stored in WebView2's autofill `Web Data`.
- **#547**: on Windows and Linux, right-click on a link shows the web view's page menu.
- **#548**: on Linux, Settings' inspector width is not exposed to AT-SPI.

The full per-row record is in `docs/verification/2026-10-18-rakazo-chat-ux.md` (#550). The lane installs without a person at the window and never opens Settings › About, so #520's installer rows are **not** credited. Its facts are posted on #520.

On the macOS runners the first choice of Kotoeri often leaves its input method unstarted, so `e61025e` chooses it afresh on later attempts; the x64 runner then composed 日本.
