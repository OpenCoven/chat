# #567 link review completion checkpoint

The objective is to make native link-review acceptance reliable across reply completion without changing the product's review security boundary. Base main is `70969a1c6e8979ab8fec28788d8939fea80e6a3d`. Work is isolated on `fix/567-link-review-race`; PR #543 and its owner worktrees are preserved.

README's existing contract closes a review when its conversation changes or source message disappears. The implementation binds to familiar/session identity and message component lifetime. That behavior is retained. A person can reopen the settled link; surviving invalidation is a different product change and is not implemented here. The review's frozen address, credential-bearing URL refusal, explicit Open, duplicate prevention and focus rules remain unchanged.

The original Windows failure is run 42532885300, attempt 1, job 128890795160, source `109f764`. Its full raw log and original artifact 13639046133 (results JSON/Markdown and screenshots) are retained in this worktree's `.artifacts/567/`. The original trace cannot distinguish a missed click from an opened-then-dismissed review; later passing retries do not resolve that ambiguity.

The ordinary native send helper previously returned at the first rendered link, before the run completed. Its regression failed with `returned=true` while completion was held. It now observes no Stop run control and an enabled composer after the transcript reload, then reacquires the link. The previous arbitrary 500 ms settling sleep is removed. Explicit streaming mode is used only by the dedicated completion row.

The native model fixture's new synthetic review reply is held until the lane has actually observed an open review. Native row 567 then releases the stream, observes the existing invalidation, verifies no browser launched, reopens the settled link and checks Escape focus return. A finally block releases a held stream on failure. Bounded accessibility-tree diagnostics distinguish `not-observed`, `open` and `opened-then-dismissed`; `not-observed` does not claim a missed click. Missing or empty accessibility trees fail the observation instead of counting as dismissal. The diagnostic contains phases, relative time and control presence, never addresses or message content.

Browser fixtures deterministically model persisted metadata shifting index-based message IDs and a completed run selecting its resulting head. Tests separately locate a live target before its replacement and open a review before scope invalidation. Both verify no implicit handoff, a fresh settled review with the exact address, and Escape focus return. Initial browser fixtures that kept persisted IDs unchanged correctly disproved an assumption that changing the head alone always removes the link DOM node; the fixture now explicitly models the documented persisted-index difference. Production code is unchanged.
