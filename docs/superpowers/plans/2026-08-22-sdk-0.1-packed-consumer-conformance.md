# Chat Packed SDK Consumer and Conformance Plan

**Status:** Active cross-repository plan  
**Date:** 2026-08-22  
**Chat base audited:** `62706597177aad3bebb518c4b99a7031e1d7a007`  
**Tracking:** [OpenCoven/chat#27](https://github.com/OpenCoven/chat/issues/27)  
**Upstream program:** [OpenCoven/sdk#31](https://github.com/OpenCoven/sdk/issues/31)

## 1. Goal

Make Chat the first real installed consumer of the OpenCoven SDK 0.1 read-only protocol.

Chat must consume exact packed SDK artifacts and complete this journey through its actual native boundary:

```text
discover Cave and Coven
→ negotiate compatibility
→ pair with explicit Cave consent
→ store the Cave credential in native custody
→ validate the live Coven peer or pipe identity
→ load canonical familiars, projects, conversations, and messages
→ restart and reconnect
→ detect Cave replacement or credential revocation
→ produce redacted conformance evidence
```

This plan does not implement send, stream, attachments, or privileged actions.

## 2. Dependency contract

Chat implementation is blocked by these SDK issues:

- [SDK #35](https://github.com/OpenCoven/sdk/issues/35) — pairing and secure credential custody
- [SDK #36](https://github.com/OpenCoven/sdk/issues/36) — canonical reads and bounded pagination
- [SDK #37](https://github.com/OpenCoven/sdk/issues/37) — CLI/native trust ownership decision

Final evidence feeds:

- [SDK #38](https://github.com/OpenCoven/sdk/issues/38) — cross-repository real-authority conformance
- [SDK #40](https://github.com/OpenCoven/sdk/issues/40) — first-release security disposition

The current `contract-canary.lock.json` pins an SDK revision from before the owner-local Coven discovery merge. It remains unchanged until a reviewed SDK candidate exposes the required public APIs and packed artifacts.

## 3. Architecture boundary

### 3.1 SDK owns protocol semantics

Chat must not duplicate:

- Cave discovery-record parsing;
- Client v1 health or envelope parsing;
- pairing request/status/exchange parsing;
- canonical read DTO parsing;
- cursor/reconciliation behavior;
- Coven discovery/config parsing;
- Coven HTTP framing or structured daemon error parsing.

Chat supplies platform/native capabilities and product state management. SDK packages supply the public protocol.

### 3.2 Native process owns secrets and live IPC identity

The webview must never receive a Cave bearer or raw keychain value.

Native code owns:

- OS-keychain credential reads/writes/deletes;
- Unix connected-socket peer credential inspection;
- Windows named-pipe ownership and connected identity inspection;
- exact packed SDK/native adapter initialization where required;
- bounded diagnostics returned to the webview;
- reconnect lifecycle events containing no secrets.

### 3.3 Canonical state remains in Cave

Chat may retain in-memory query state and, in a later milestone, an encrypted replaceable read cache. It does not create a second canonical database, synthesize private route DTOs, or persist bearer-authenticated response bodies in browser storage.

### 3.4 Trust never degrades for convenience

Forbidden fallbacks:

- pathname-only Unix trust;
- constructed Windows pipe names;
- PowerShell, `lsof`, or shell-command identity checks;
- private Node internals;
- plaintext files, environment variables, localStorage, or IndexedDB for credentials;
- workspace/source imports used as release evidence;
- direct fetches to Cave private routes.

## 4. Proposed file ownership

The exact names may change during implementation, but ownership must remain narrow.

### Native/Tauri

- `src-tauri/src/sdk_connection.rs` — native SDK/client lifecycle and command boundary
- `src-tauri/src/cave_credentials.rs` — OS-keychain-backed `SecretStore`
- `src-tauri/src/coven_peer_identity.rs` — Unix connected-peer adapter
- `src-tauri/src/coven_pipe_identity.rs` — Windows pipe ownership/connected identity adapter
- `src-tauri/src/sdk_diagnostics.rs` — allowlisted native diagnostics
- `src-tauri/src/lib.rs` — command/event registration only

If a shared Rust trust crate is approved by SDK #37, Chat wraps that crate rather than reimplementing OS-specific logic.

### TypeScript/webview

- `src/lib/sdk/native-boundary.ts` — typed invoke/event wrapper with validation
- `src/lib/sdk/connection-controller.ts` — explicit state machine, no bearer values
- `src/lib/sdk/query-adapter.ts` — canonical read/query integration
- `src/lib/sdk/diagnostics.ts` — presentation-safe diagnostics
- `src/lib/sdk/*.test.ts` — state, ordering, and redaction tests

### Canary and evidence

- `contract-canary.lock.json` — exact repository revisions and artifact digests
- `scripts/contract-canary.mjs` — exact packed artifact producer/consumer check
- `scripts/sdk-real-authority-conformance.mjs` — isolated release-mode journey or adapter into the shared evidence runner
- `docs/workflows/sdk-packed-consumer-conformance.md` — operator runbook
- `docs/sdk-conformance-results/*.json` — redacted release-gate evidence where approved

## 5. Connection state model

The product state must distinguish cause and authority explicitly:

```ts
type SdkConnectionState =
  | { state: "idle" }
  | { state: "discovering" }
  | { state: "incompatible"; diagnosticId: string }
  | { state: "pairing_required"; caveInstanceId: string }
  | { state: "pairing"; requestId: string; expiresAt: number }
  | { state: "ready"; caveInstanceId: string; covenAvailable: boolean }
  | { state: "revoked"; diagnosticId: string }
  | { state: "offline"; lastHealthyAt: string | null; diagnosticId: string }
  | { state: "error"; code: string; diagnosticId: string };
```

No branch contains a bearer, pairing secret, raw native error, command output, full filesystem path, prompt, message body, or attachment metadata.

## 6. Implementation waves

## Wave A — freeze the native adapter contract

Blocked by SDK #37.

- [ ] Decide whether the OS-specific trust implementation is shared Rust, Chat-owned Rust, or an SDK-distributed native package.
- [ ] Freeze the adapter signatures expected by `@opencoven/coven-client`.
- [ ] Freeze the native `SecretStore` service/account identity and migration policy.
- [ ] Define supported OS/architecture matrix and unavailable-backend behavior.
- [ ] Add failing native tests for wrong peer UID, unavailable peer credentials, foreign pipe owner, connected identity mismatch, and keychain unavailable.

**Exit gate:** no Chat code needs to weaken an SDK trust requirement or invent an unreviewed native interface.

## Wave B — update the packed canary

Blocked by stable packed APIs from SDK #34–#36.

- [ ] Produce exact SDK tarballs through the SDK artifact producer.
- [ ] Verify tarball SHA-256 values against the producer manifest.
- [ ] Install into an isolated temporary consumer with a cold workspace graph.
- [ ] Compile/import every package Chat uses.
- [ ] Run a deterministic mock-authority smoke without repository-relative imports.
- [ ] Extend `contract-canary.lock.json` with SDK artifact digests and exact authority revisions.
- [ ] Fail when the lock references an unavailable commit, wrong digest, or mismatched package set.

**Exit gate:** the canary proves installability and public signatures from exact artifacts, not source compatibility inside the monorepo.

## Wave C — native discovery, health, and pairing

Blocked by SDK #34 and #35.

- [ ] Invoke Cave discovery and normalized health through the public SDK.
- [ ] Invoke Coven discovery/health with the live native identity adapters.
- [ ] Start pairing only after compatibility succeeds.
- [ ] Keep the pairing secret inside the native command scope.
- [ ] Hand the issued bearer directly to native `SecretStore` custody.
- [ ] Return only credential metadata and bounded state to the webview.
- [ ] Implement denial, expiry, rate limit, replay, secure-store failure, and incompatible-version states.
- [ ] Implement local forget without describing it as server revocation.

**Exit gate:** a release-mode Cave can be discovered and paired without a bearer entering the webview or logs.

## Wave D — canonical reads

Blocked by SDK #36 and Wave C.

- [ ] Load familiars and projects after `ready`.
- [ ] Load bounded conversation pages.
- [ ] Load one conversation and bounded message pages.
- [ ] Preserve `reconcile_required` as a canonical reload state (explicitly define whether this is query-layer state or part of `SdkConnectionState`).
- [ ] Reject stale delayed responses after Cave instance replacement or request-generation change.
- [ ] Keep canonical identities from the SDK DTOs; do not remap them to harness-private IDs.
- [ ] Persist no authenticated response in browser storage.

**Exit gate:** the Chat surface can navigate the complete read-only Client v1 state using only public packed SDK DTOs.

## Wave E — restart, relocation, and revocation

- [ ] Restart Chat and reuse the native credential when still valid.
- [ ] Restart Cave at the same installation and reconnect through a fresh discovery record.
- [ ] Detect a different Cave instance at the same endpoint and invalidate stale assumptions.
- [ ] Recover from endpoint relocation without accepting an unvalidated endpoint.
- [ ] Detect remote credential revocation on the next authenticated operation.
- [ ] Separate temporary offline, incompatible, revoked, and wrong-instance states.
- [ ] Never automatically re-pair or widen scope after a failure.

**Exit gate:** lifecycle recovery preserves identity and authority boundaries instead of merely restoring transport connectivity.

## Wave F — real-authority evidence

Feeds SDK #38.

- [ ] Run against an isolated release-mode Cave and real Coven daemon.
- [ ] Exercise the full create/pending/approve/exchange/read/restart/revoke journey.
- [ ] Exercise live Unix or Windows IPC identity checks.
- [ ] Record exact commits, OS/architecture, versions, and artifact digests.
- [ ] Declare the complete expected assertion ID set.
- [ ] Fail on missing, duplicate, unexpected, or silently omitted assertions.
- [ ] Retain no credentials or user content.
- [ ] Prove the operator’s real Cave/Coven homes and keychain records are untouched.
- [ ] Remove `sdk` and `chat` from the read-only journey’s `notCovered` list.

## 7. PR sequence

Recommended implementation PRs:

1. `feat/native-sdk-trust-adapters` — Wave A
2. `test/packed-sdk-canary-0.1` — Wave B
3. `feat/sdk-discovery-pairing-connection` — Wave C
4. `feat/sdk-canonical-read-integration` — Wave D
5. `fix/sdk-lifecycle-recovery` — Wave E
6. `test/sdk-real-authority-conformance` — Wave F

Each PR must state:

- upstream SDK commit/artifacts used;
- dependency issues;
- public/native API changes;
- secret and identity data flow;
- platform coverage;
- exact tests and packed evidence;
- remaining blockers;
- explicit non-goals.

Avoid one cross-repository mega-PR. Native trust, canary packaging, protocol connection, canonical UI reads, lifecycle recovery, and release evidence should remain independently reviewable.

## 8. Required tests

### Native trust

- live correct Unix UID;
- wrong UID;
- adapter failure/timeout;
- pathname replacement after connect;
- correct Windows owner/identity;
- foreign owner;
- connected pipe mismatch;
- unavailable native backend;
- no PowerShell/shell fallback.

### Credential custody

- set/get/delete round trip;
- missing binding;
- keychain locked/unavailable;
- corrupt legacy record;
- concurrent pairing completion;
- no bearer in command return/event/log;
- restart reuse;
- remote revocation.

### Connection state

- no authority running;
- stale discovery;
- incompatible client;
- pairing pending/denied/expired/rate-limited;
- secure-store write failure;
- Cave instance replacement;
- Coven unavailable while Cave remains ready;
- cancellation and total deadlines.

### Canonical reads

- empty and paged lists;
- wrong scope/revoked credential;
- cursor replay;
- malformed cursor;
- mutable conversation walk limitation;
- active-branch message reconciliation;
- stale response ordering;
- no browser persistence.

### Canary/evidence

- wrong SDK commit;
- wrong artifact digest;
- workspace-link contamination;
- source checkout unavailable;
- missing expected assertion;
- duplicate assertion;
- redaction failure;
- operator-state mutation detection.

## 9. Security and privacy invariants

The implementation fails review if any of these become possible:

- bearer or pairing secret enters the webview;
- credential falls back to plaintext storage;
- Chat constructs a Coven socket/pipe identity from naming conventions;
- a live peer/pipe check is skipped because the endpoint path looked safe;
- Chat calls Cave private routes to fill a missing SDK API;
- raw native/SDK causes are serialized into diagnostics;
- response bodies or prompts enter retained evidence;
- an old Cave instance’s credential/state is silently applied to a new instance;
- a packed canary passes through workspace links;
- conformance reports success while an expected leg is absent.

## 11. Completion definition

Chat #27 closes only when:

- exact SDK tarballs install and compile in the canary;
- live Cave discovery, pairing, restart, canonical reads, and revocation pass;
- live Coven peer/pipe validation and health pass;
- no bearer enters the webview or retained evidence;
- supported platforms have native evidence;
- the lockfile names exact revisions and artifact digests;
- the evidence is accepted by SDK #38;
- all implementation PR review threads affecting correctness or trust are resolved.
